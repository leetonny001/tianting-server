## 1. 需要你拍板的（3 条）

| # | 问题 | 产品答复 |
|---|---|---|
| C-01 | **被踢下线后的交互**（矛盾）：AC-AUTH-03-6 要求"发送中的消息显示失败"，但 F-AUTH-03 又要求被踢后立即回登录页、清空内存，用户根本看不到这条失败消息 | 被踢后**停留在当前页面并弹出提示框**（显示原因），此时发送中的消息显示为失败；用户点"确定"后再回到登录页并清空数据 |
| C-02 | **打开"历史可见"后未读数会暴涨**：新成员入群时未读为 0，管理员把 `historyVisible` 从 false 改为 true 后，按现在的公式未读会从 0 跳到 10 | 未读数**始终从入群时刻开始算**：未读 = maxSeq − max(readSeq, joinSeq)。`historyVisible` 只决定"能不能翻到"，不影响未读数（入群前的历史可以看，但不算未读） |
| C-03 | **超过 500 个会话**怎么办 | 返回最近更新的 500 个，并带上 `truncated: true`；一期界面不处理（实际场景很难超过 500 个） |

## 2. PRD 矛盾，产品直接修正（4 条）

| # | 问题 | 修正 |
|---|---|---|
| C-04 | "单次批量最多 500 人"与"建群 2000 人成功"（AC-GRP-01-3）冲突 | 500 的批量上限只适用于**加成员接口和导入用户接口**；建群的初始成员只受 2000 总数限制，2001 人返回 4130 |
| C-05 | 4009（平台不合法）被归为"连接级致命错误，先发 kicked"，但 kicked 的原因列表里没有对应的值 | 平台不合法属于开发期缺陷：**不发 kicked**，直接以 4009 关闭。F-SYS-01 规则 2 改为只适用于 4010～4012 |
| C-06 | F-SYNC-02 没有规则，第 8 节也没有定义已读同步事件 | 第 8 节补充 P1 的 `event/readUpdated {convId, readSeq}`；F-SYNC-02 补充规则：已读位置前进时，推送给该用户的其他连接 |
| C-07 | sync 200 条 × 每条 5000 字，响应会远超 64KB，而 64KB 是单帧上限 | 64KB 只限制**上行**（客户端发给服务端）的帧；下行不设帧大小上限，SDK 不得设置下行读取上限 |

## 3. 细化（产品直接定，合并进 v1.1）

### 3.1 错误码与鉴权

| # | 问题 | 答复 |
|---|---|---|
| C-08 | 多个错误同时出现时，报哪个错误码 | 连接时的检查顺序：平台（4009）→ 签名 / 格式（4010）→ 强制下线（4012）→ 过期（4011）。群管理接口：格式（4004 / 4000）→ 群是否存在（4043）→ 批量上限（4131）→ 用户是否存在（4042）→ 总人数（4130） |
| C-09 | 未定义的错误码落在已知子区段（如 4049、4299）时怎么兜底 | 按**前三位**兜底：403x 提示"无权限"、404x 提示"内容不存在"、429x 提示"发送太频繁"，其余 4xxx 提示"请求出错"；未定义的 5xxx 视为可重试，提示"服务异常，请稍后重试" |
| C-10 | KMP SDK 的错误枚举一致性测试是否纳入一期验收 | 不纳入：一期没有 KMP SDK，放到 M5 |
| C-11 | "强制下线之前签发"的判断精度：按秒记录的话，下线后同一秒内重新签发的 token 会被误判作废 | token 携带**毫秒级**签发时间（自定义字段 `iatMs`），按毫秒比较 |
| C-12 | 强制下线一个不存在的用户 | 返回 HTTP 404 / 4042 |
| C-13 | 非测试模式下 `ttlSeconds` 的下限 | 最小 60 秒，小于 60 按 60 签发 |
| C-14 | platform 是否区分大小写 | 区分；只接受小写 |
| C-15 | 新接口路径 | 导入用户 `POST /admin/users/import`；查询用户 `GET /admin/users/{userId}`（新增，用于核对导入结果）；强制下线 `POST /admin/users/{userId}/force-logout`；演示登录 `POST /demo/login` |

### 3.2 用户

| # | 问题 | 答复 |
|---|---|---|
| C-16 | 昵称超过 32 字、头像超过 512 字符 | 返回 4000，整批都不写入 |
| C-17 | 导入空数组、同一批里 userId 重复 | 空数组返回 4000；同一批里重复时以最后一条为准 |
| C-18 | userId 是否区分大小写 | 区分（`Alice` 和 `alice` 是两个用户） |
| C-19 | 昵称修改后，在线客户端怎么刷新 | 下次拉取 `convs` 时生效，一期不做实时推送（P1） |
| C-20 | 头像首字母占位规则 | 取显示名的第一个字符（码点），英文转大写；背景色按 userId 哈希取色 |
| C-21 | 演示登录的用户名 | 先去首尾空白；为空返回 4004；签发的 token 有效期 1 天，测试模式下可以传 `ttlSeconds` |

### 3.3 连接

| # | 问题 | 答复 |
|---|---|---|
| C-22 | 退避上限 30 秒是加抖动之前还是之后；重连成功后是否重置 | 上限指**加抖动之前**（实际间隔落在 24～36 秒）；重连成功后，退避重置为 1 秒 |
| C-23 | "提示立即消失"怎么量化；"连接中…"和"网络不可用"什么时候切换 | 恢复后 500ms 内消失；浏览器处于离线状态时显示"网络不可用"，其余断开情况（正在重连）显示"连接中…" |
| C-24 | 缺口超过 200 时，"最新一页"是多少条；未读显示多少；群要不要考虑 minSeq | 最新一页为 20 条；未读数按服务端返回的真实值显示；群会话的补拉起点取 max(本地 maxSeq, minSeq − 1) |
| C-25 | 按生产参数验证"5 分钟保活"要不要跑 | 只在每晚构建和手工回归中跑，日常 CI 用缩短后的参数 |

### 3.4 消息

| # | 问题 | 答复 |
|---|---|---|
| C-26 | 哪些字符算空白 | 以 Unicode `White_Space` 属性为准（含 `\r`、U+00A0、U+3000 等 25 个字符）；**U+200B、U+FEFF 不算空白**。服务端和 SDK 使用同一张字符表，并共用同一批测试数据 |
| C-27 | ZWJ 组合 emoji 按码点计数（一家人 emoji 算 5 个，国旗算 2 个），是否是预期行为 | 是预期行为：按码点计数简单，而且前后端容易一致 |
| C-28 | 超过 5000 字时，发送按钮是置灰还是点了才提示 | 输入框下方实时显示"已超出 N 字"，同时发送按钮置灰 |
| C-29 | 限流是固定窗口还是滑动窗口；被拒绝的请求、去重命中的重发算不算次数 | 令牌桶算法（容量 20，每秒补充 20 个）；被 4290 拒绝的请求和去重命中的重发**都不计数** |
| C-30 | 10 秒超时标记失败后，ack 又到了 | 以 ack 为准，变为"已发送" |
| C-31 | clientMsgId 长度不在 8～64 之间 | 返回 4000 |
| C-32 | sync 的 limit ≤ 0，或 afterSeq / beforeSeq 同时出现或都不出现 | 返回 4000 |
| C-33 | 消息列表的时间显示：第一条是否显示、跨天但间隔不到 5 分钟是否显示 | 当前已加载的第一条消息总是显示时间；跨天总是显示时间 |
| C-34 | 自己从另一台设备发出的消息，在本设备上算不算未读 | 不算：客户端收到 `from` 是自己的消息时，不增加未读数，并推进本地 readSeq |
