## 1. 背景与目标

### 1.1 背景

PRD-core 定义了一期核心业务和 H5 的页面清单（第 5 节），但只到"有哪些页面、显示什么"，没有统一的信息架构、布局、视觉和交互细节。后续 PC（Tauri 壳加载同一套 web）、Android（Compose）、iOS（SwiftUI）都要按同一份规范实现，需要一份各端共用的交互规范。

### 1.2 目标

1. 定义各端统一的信息架构（消息 / 通讯录 / 我）和页面交互，**参考微信的信息架构和交互习惯**，降低用户学习成本。
2. 定义一套自有品牌的视觉规范（设计 token、浅色 / 深色、气泡、头像），各端共用。
3. 在 PRD-core 第 5 节之上细化，**不改变 PRD-core 已定义的业务规则和 AC**；需要服务端或 SDK 新增能力的，列为缺口（第 7 节）由 Frank 取舍。

### 1.3 实施顺序

| 端 | 时间 | 说明 |
|---|---|---|
| H5 | M3（一期） | 本 PRD 的 AC 首先在 H5 上验证 |
| PC | M4 | Tauri 壳加载同一套 web 代码，使用"宽屏布局" |
| Android / iOS | M5 / M6 | 按本 PRD 的交互和视觉规范实现；平台差异见 3.3 节 |

### 1.4 品牌与知识产权约束（强制）

**参考微信的信息架构和交互模式，但不复制微信的商标、图标、品牌色和视觉资产。** 具体规则：

| # | 规则 |
|---|---|
| B-1 | 产品名、Logo、App 图标、启动页使用自有设计；界面文案、页面标题、`<title>`、安装包名、商店描述中不得出现"微信""WeChat"及其图形标识 |
| B-2 | 不使用微信的品牌绿（`#07C160` 及相近色）作为品牌色、主按钮色或"自己的气泡"颜色。判定规则：HSL 色相在 120°～165° 且饱和度 > 40% 的颜色不得用作 `color.brand*`、`color.bubble.self*` token |
| B-3 | 不使用从微信提取或描摹的图标、插画、表情图、提示音、动效；图标使用自绘或开源许可的图标库（如 Lucide，ISC 许可），许可证文件随代码提交 |
| B-4 | 不使用微信的界面截图作为素材（包括分享会幻灯片里的"对比图"应注明"参考"并与本产品截图明显区分） |
| B-5 | 可以借鉴的是通用交互模式：底部三栏导航、会话列表 + 聊天页、左右气泡、长按菜单、时间分隔、失败感叹号重发等。这些模式在主流 IM 中普遍存在 |
| B-6 | 品牌名和品牌色见 D-UI-02；拍板前，文档和代码中用占位名 `{产品名}`，token 前缀统一用 `--im-` |

## 3. 信息架构

### 3.1 导航结构

一级导航三项，顺序固定：

| 一级 | 路由 | 内容 |
|---|---|---|
| 消息 | `/chats` | 会话列表（首页） |
| 通讯录 | `/contacts` | 见 F-UI-13（一期方案待 D-UI-01） |
| 我 | `/me` | 当前账号信息、设置入口 |

二级页面：

| 页面 | 路由 | 从哪里进入 |
|---|---|---|
| 登录 | `/login` | 未登录时任意路由重定向到这里 |
| 聊天页 | `/chat/:convId` | 会话列表、通讯录、资料卡 |
| 聊天信息 | `/chat/:convId/info` | 聊天页顶栏右侧"更多"按钮 |
| 群成员列表 | `/chat/:convId/members` | 聊天信息页（P1） |
| 资料卡 | `/user/:userId` | 通讯录、聊天页头像、群成员（P1） |
| 设置 | `/me/settings` | 我 |
| 群聊列表 | `/contacts/groups` | 通讯录 |

`convId` 在路由中做 URL 编码（单聊 ID 含 `:`）。

### 3.2 布局

| 项 | 窄屏（宽度 < 768px） | 宽屏（宽度 ≥ 768px） |
|---|---|---|
| 一级导航 | 底部标签栏（高 56 + 底部安全区），图标 + 文字 | 左侧竖向导航栏（宽 64），顶部是当前用户头像，下面三个图标；"设置"固定在底部 |
| 页面组织 | 单栏，页面跳转；二级页面隐藏底部标签栏 | 三栏：导航栏 64 / 列表栏 280 / 主区（剩余宽度，最小 424） |
| 打开会话 | 跳转到聊天页，顶栏左侧有返回按钮 | 主区显示聊天页，列表栏中该会话高亮；无返回按钮 |
| 主区空态 | — | 未选中会话时，主区显示产品 Logo 和"选择一个会话开始聊天" |
| 聊天信息 / 成员 / 资料卡 | 新页面 | 主区右侧滑出的侧板（宽 360），点击遮罩或 Esc 关闭 |
| 通讯录 | 列表页 → 资料卡页 | 列表栏显示通讯录，主区显示资料卡 |
| 我 / 设置 | 页面 | 列表栏显示"我"，主区显示设置内容 |
| 弹窗（发起单聊、确认框） | 居中弹窗，宽 = 屏宽 − 48 | 居中弹窗，宽 400 |

同一个 URL 在两种布局下都能直接打开：例如宽屏打开 `/chat/:convId` 时列表栏和主区同时显示。窗口宽度跨过 768px 时实时切换布局，当前路由不变。Tauri 窗口最小尺寸 800×560。

### 3.3 各端差异

| 项 | H5（窄屏） | PC（宽屏，Tauri） | Android | iOS |
|---|---|---|---|---|
| 布局 | 窄屏 | 宽屏三栏 | 窄屏（平板横屏可用宽屏，P2） | 窄屏（iPad 可用宽屏，P2） |
| 返回 | 顶栏返回 + 浏览器返回 | 无（三栏） | 顶栏返回 + 系统返回键 / 手势 | 顶栏返回 + 边缘右滑 |
| 消息菜单 | 长按 500ms | 右键 | 长按 | 长按 |
| 发送 | 键盘"发送"键 / 发送按钮 | Enter 发送，Shift+Enter 换行 | 发送按钮 | 键盘"发送"键 / 发送按钮 |
| token 存储 | `sessionStorage`（D4） | 同 H5（同一套 web 代码） | 由原生 PRD 定（建议 EncryptedSharedPreferences） | 由原生 PRD 定（建议 Keychain） |
| 主题 | 跟随系统 + 手动 | 同 H5 | 跟随系统 + 手动 | 跟随系统 + 手动 |

原生端的 AC 在其各自的任务单里引用本 PRD 的 AC 编号；本 PRD 的 AC 默认在 H5 上验证。

## 4. 功能需求

> 每个功能点：描述 → 规则 → 验收标准（AC）。PRD-core 已定义的规则只引用、不重复。

### F-UI-01 信息架构与导航（P0）

**规则**
1. 一级导航为"消息、通讯录、我"三项（3.1 节），当前项高亮（品牌色图标 + 文字）。
2. 已登录状态下访问 `/login` 跳转到 `/chats`；未登录访问任意路由跳转到 `/login`，登录成功后回到原路由。
3. 点击当前已选中的"消息"标签，会话列表滚动到顶部。
4. 浏览器前进 / 后退与页面切换一致；刷新后停留在当前路由（PRD-core 第 5 节"刷新行为"）。

**验收标准**
- AC-UI-01-1【前端】【窄屏】：已登录进入 `/chats`，底部标签栏显示"消息、通讯录、我"三项，"消息"处于选中态；点击"我"后路由为 `/me`，"我"处于选中态。
- AC-UI-01-2【前端】【宽屏】：已登录进入 `/chats`，左侧导航栏显示三个导航项，不显示底部标签栏。
- AC-UI-01-3【前端】：未登录直接打开 `/chat/c2c%3Aa%3Ab`，跳转到 `/login`；登录成功后进入 `/chat/c2c%3Aa%3Ab`。
- AC-UI-01-4【前端】：已登录打开 `/login`，跳转到 `/chats`。
- AC-UI-01-5【前端】【窄屏】：从会话列表进入聊天页后点浏览器后退，回到会话列表，且列表滚动位置与进入前一致（误差 ≤ 1 个列表项高度）。
- AC-UI-01-6【前端】【窄屏】：进入聊天页、聊天信息页、设置页时，底部标签栏不显示。

### F-UI-02 响应式布局（P0）

**规则**：按 3.2 节。断点 768px；布局切换不改变路由、不重新连接、不丢失输入框内容。

**验收标准**
- AC-UI-02-1【前端】【宽屏】：打开 `/chat/:convId`，同时可见导航栏、会话列表（该会话高亮）、聊天主区；聊天页顶栏无返回按钮。
- AC-UI-02-2【前端】【宽屏】：打开 `/chats`，主区显示"选择一个会话开始聊天"。
- AC-UI-02-3【前端】：在聊天页输入框输入"草稿"，把视口从 1280 宽改为 375 宽，路由不变、输入框内容仍为"草稿"、SDK 连接未断开（服务端日志无新的连接建立）。
- AC-UI-02-4【前端】：视口宽 767 时为窄屏布局，768 时为宽屏布局。
- AC-UI-02-5【前端】：在 320×568 视口下，所有一级页面和聊天页没有横向滚动条（`document.documentElement.scrollWidth ≤ 320`）。

### F-UI-03 登录页（P0，细化 F-AUTH-04）

**描述**：一期走演示登录服务（F-AUTH-04）：输入用户名即可登录。接入业务方时由业务方提供 token，不经过此页。

**规则**
1. 页面元素：产品 Logo 和名称、"用户名"输入框、"登录"按钮、底部说明"演示环境：输入任意用户名即可登录"。
2. 输入框去首尾空白后为空时，"登录"按钮不可点；回车等同点击"登录"。
3. 提交前按 `userId` 规则在前端校验（PRD-core 3.1 节），不合法提示"账号格式不正确"（AC-AUTH-04-4）。
4. 提交后按钮显示加载态并禁用，防止重复提交；成功后进入 `/chats`（或 F-UI-01 规则 2 的原路由）。
5. 失败文案：演示登录接口返回 404（未开启）→"登录服务未开启"；网络错误或超时（10 秒）→"网络异常，请稍后重试"；其余按 F-UI-19。
6. 输入框字号 ≥ 16px（防止 iOS Safari 聚焦时自动放大页面）。

**验收标准**
- AC-UI-03-1【前端】：输入框为空或只有空格时"登录"按钮为禁用态；输入"alice"后可点。
- AC-UI-03-2【前端】：输入"alice"按回车，发出 1 次 `/demo/login` 请求，成功后进入 `/chats`。
- AC-UI-03-3【前端】：在登录请求返回前连续点击"登录" 3 次，只发出 1 次请求。
- AC-UI-03-4【前端】：演示登录服务未开启（返回 404）时提示"登录服务未开启"，停留在登录页。
- AC-UI-03-5【前端】：登录请求 10 秒无响应（拦截请求不返回），提示"网络异常，请稍后重试"，按钮恢复可点。
- AC-UI-03-6【前端】：登录页用户名输入框的计算字号 ≥ 16px。
- （引用）AC-AUTH-04-1、AC-AUTH-04-2、AC-AUTH-04-4。

### F-UI-04 会话列表（P0，细化 F-CONV-01 / F-CONV-02）

**规则**
1. 顶栏：标题"消息"（窄屏居中，宽屏在列表栏顶部左对齐）；右侧"+"按钮，点开菜单，一期只有"发起单聊"一项（F-UI-05）。
2. 连接状态条位于顶栏下方（F-UI-17）。
3. 会话项（高 72）：左侧头像 48（F-UI-21）；第一行显示名（单行省略）+ 右侧时间；第二行摘要（单行省略，C-40）。
4. 未读角标：在头像右上角，红底白字，>99 显示"99+"，0 不显示（AC-CONV-02-4、C-41）。
5. 摘要规则：
   - 群聊且最后一条消息不是自己发的：`{发送者显示名}: {摘要}`；单聊或自己发的：只显示摘要。
   - `lastMsg` 为 `null`（没有消息的群，C-39）：不显示摘要和时间。
   - 消息类型为 `custom`（摘要为空字符串）：显示"[消息]"。
   - 有草稿时：显示"[草稿] {草稿内容}"，"[草稿]"用危险色（F-UI-24，P1）。
6. 时间：取 `lastMsg.ts`，按 F-MSG-06 规则 4 的会话列表格式。
7. 排序、新消息置顶沿用 F-CONV-01、AC-CONV-01-2；`truncated = true` 时在列表底部显示"仅显示最近 500 个会话"。
8. 点击会话项进入聊天页；宽屏下当前打开的会话高亮（`color.surface.selected`）。
9. 不提供左滑删除、置顶、免打扰（F-CONV-01 规则 4）；长按 / 右键会话项一期无菜单。

**验收标准**
- AC-UI-04-1【前端】：群 g1 最后一条消息由 bob 发出、内容"晚上好"，会话项摘要为"bob: 晚上好"；我自己在 g1 发"收到"后，摘要变为"收到"。
- AC-UI-04-2【前端】：单聊最后一条消息由对方发出，摘要不带发送者前缀。
- AC-UI-04-3【前端】：没有消息的群（`lastMsg = null`）显示群名，不显示摘要和时间。

### F-UI-19 轻提示与错误文案（P0，细化 F-SYS-01）

**规则**
1. 轻提示（toast）：窄屏底部居中（输入区上方）、宽屏顶部居中；显示 2 秒；同时只显示 1 条，新的替换旧的；不打断操作。
2. 文案只按错误码映射，**不展示服务端 `msg`**（PRD-core 3.1 节）；映射表集中维护（FE-016），以 PRD-core 第 5 节文案表为准，本 PRD 补充：

| 场景 | 文案 | 来源 |
|---|---|---|
| 4429（被踢） | 登录设备过多，当前设备已下线 | AC-AUTH-02-10 |
| 4005 | 不能发送空白消息 | ERRORS.md |
| 4030 | 无权限 | ERRORS.md |
| 4040 | 内容不存在 | ERRORS.md |
| 未定义的 4xxx | 请求出错 | AC-SYS-01-4、C-09 |
| 未定义的 5xxx | 服务异常，请稍后重试 | C-09 |
| 演示登录 404 | 登录服务未开启 | 本 PRD F-UI-03 |
| 登录网络错误 / 超时 | 网络异常，请稍后重试 | 本 PRD F-UI-03 |
| 复制成功 | 已复制 | 本 PRD F-UI-09 |
| 会话截断 | 仅显示最近 500 个会话 | C-03 |
| 复制失败 | 复制失败，请长按文字手动复制 | 本 PRD 9.3 节 |

3. 4033、4042 等"需要用户知道"的错误：轻提示 + 消息标记失败；4000、4002、4003、4007、4008 等开发期缺陷：只写日志，消息标记失败，轻提示"请求出错"。

**验收标准**
- AC-UI-19-1【前端】：连续触发两个错误提示，屏幕上只同时存在 1 条轻提示，内容为后一条；2 秒（±0.3 秒）后消失。
- AC-UI-19-2【前端】：服务端返回 `{code:4042, msg:"user not found xyz"}` 时，界面显示"用户不存在"，页面任何位置都搜不到"user not found xyz"。
- AC-UI-19-3【前端】：映射表覆盖 `errors.json` 中所有 ws 通道的错误码（单元测试遍历 `errors.json`，每个码都能得到非空文案）。
- （引用）AC-SYS-01-4。

### F-UI-22 主题：浅色 / 深色（P0 浅色 / P1 深色，待 D-UI-07）

## 6. 视觉规范

| `color.on.brand` | `#FFFFFF` | `#FFFFFF` | 品牌色上的文字 |

| `color.surface` | `#FFFFFF` | `#1B1E25` | 列表、卡片、顶栏 |
| `color.surface.selected` | `#E8EBFA` | `#2A2F45` | 宽屏选中会话 |
| `color.chat.bg` | `#EEF0F4` | `#0D0F13` | 消息列表背景 |

### 6.2 字号、间距、圆角、尺寸

| 类别 | token | 值 |
|---|---|---|
| 字号 | `font.caption` / `font.small` / `font.body` / `font.title` / `font.large` | 12 / 14 / 16 / 17 / 22（px，行高 1.4～1.5） |
| 字体 | `font.family` | `-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`（不打包字体文件） |
| 间距 | `space.1`～`space.6` | 4 / 8 / 12 / 16 / 24 / 32 |
| 圆角 | `radius.sm` / `radius.md` / `radius.lg` / `radius.group` / `radius.full` | 4 / 8 / 12 / 10 / 50% |
| 尺寸 | 顶栏 / 标签栏 / 会话项 / 状态条 | 48 / 56 / 72 / 36（+ 安全区） |
| 头像 | 列表 / 聊天 / 资料 / 导航 | 48 / 40 / 64 / 36 |
