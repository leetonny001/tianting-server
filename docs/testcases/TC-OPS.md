# 测试用例：运维后台（OPS）

> 依据：[PRD-ops v1.0](../prd/PRD-ops-v1.1.md)（冻结，167 条 AC：第一批 159 条，其中 5 条依赖 B6；第二批 7 条；P1 1 条）、[PRD-admin v1.0](../prd/PRD-admin-v1.0.md) 第 4 节公共基座与 F-KEY-03、2.3 / 2.4 节、第 10 节错误码，[ERRORS.md](../../protocol/ERRORS.md)，[内存分析](../reports/mem-2026-11-03.md)，[压测报告](../reports/perf-2026-11-03.md)。任务单：[backend-ops](../tasks/backend-ops.md)、[console-ops](../tasks/console-ops.md)、[frontend-ops](../tasks/frontend-ops.md)。
>
> 通用约定：
> - 环境（PRD-ops 3.3 节）：**E1 单节点**（1 个 im-server，development，`IM_TEST_MODE=1`，`IM_NODE_ID=n1`；console-server 基座测试模式 `CON_TEST_MODE=1`；Postgres、Prometheus、Alertmanager、Grafana、webhook 接收器、MinIO、node_exporter textfile）；**E2a 静态双节点**（E1 + n2，同一 JWT 密钥、各自 SQLite、静态节点列表，无 Redis / NATS / Presence）；**E2b 集群**（B6 交付的 Redis + NATS + Postgres，依赖 B6）；**EP 性能**（`im-loadtest` 驱动的 E1，服务端与压测客户端同机，结论只在同一轮内比较，C-50）；**单测**；**promtool**。环境编排见 BE-320，Postgres / Grafana / Prometheus / Alertmanager / MinIO 等由测试环境提供，不在开发机安装。
> - 时钟：**[C 钟]** 为 console-server 注入时钟（`POST /console/test/clock`），驱动会话、锁定、step-up、票据、每日配额、版本不一致计时、备份距今；**[IM 钟]** 为 im-server 注入时钟（`POST /admin/test/clock`），驱动 token 有效期和签名时间戳窗口。需要同时推进时用 `tools/set-clocks.sh`（先 [IM 钟] 后 [C 钟]）。
> - 账号：运维空间 `su1`、`su2`（`ops_superadmin`）、`view1`、`view2`（`ops_viewer`）、`eng1`、`eng2`（`ops_engineer`，另有 20 个性能测试账号 `perf01`～`perf20`）、`aud1`、`aud2`（`ops_auditor`）；管理空间 `adm_super`（`super_admin`）、`adm_aud`（`auditor`）、`adm_cs`（客服）。终端用户 `u1`、`u2`…；`u999` 从未存在。除特别说明，账号均已激活并绑定 TOTP，操作需要重新验证时已在 5 分钟内重新验证。
> - 网络：VPN 测试机 `10.8.1.2`；运维空间网段 `10.8.0.0/16`；网段外地址 `192.168.1.2`；console-server 所在网段 `10.8.2.0/24`（节点 `IM_OPS_ALLOWED_CIDRS`）。
> - 错误响应："返回 401"（会话无效）一律指 HTTP 401 / 4014；节点签名失败 401 / 4017；权限不足 403 / 4030；审计写失败 503 / 5031（PRD-admin 第 10 节）。
> - 批次：优先级 P0 为第一批验收；标"B6 前置，不计入第一批验收"的用例在 B6 之后执行；"第二批""P1"的用例不计入第一批。
> - 性能用例按 PRD 口径：同一轮压测中"关 / 开"交替 3 次、每段 5 分钟，取各段 P99 的中位数比较，并要求每段 P99 绝对值达标；不用百分比劣化。
> - 层级：后端 e2e（Go e2e，对 console-server / im-server 接口断言）、UI 自动化（Playwright）、部署 e2e（部署后的 Prometheus / Grafana / Alertmanager / 备份脚本 / 防火墙）、单测、promtool、性能、手工。
