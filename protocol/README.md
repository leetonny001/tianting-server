# IM 协议（v0 草案）

协议的唯一真相源。服务端、`sdk-kmp`、`sdk-ts` 都以这里为准，并跑同一批用例。

| 文件 | 内容 |
|---|---|
| `schema/frame.schema.json` | WebSocket 帧的 JSON Schema（2020-12） |
| `vectors/frames.json` | 单帧校验用例：`valid` 必须通过，`invalid` 必须拒绝 |

## 连接

```
ws(s)://{host}/ws?token={jwt}&platform={android|ios|web|pc}
```

- token 由业务服务端调用 `POST /admin/users/token` 获取（对应腾讯 IM 的 userSig）。
- 鉴权失败：HTTP 401，不升级 WebSocket。
- 每个 WebSocket 消息是一帧 JSON（text frame），一帧一个对象。

## 交互规则

1. 带 `id` 的请求，服务端必定回一个同 `id` 的 `ack`：成功时带 `data`，失败时带 `error`，两者不会同时出现。
2. `msg` / `push` / `event` 是服务端主动下发，没有 `id`，客户端不需要回复。
3. 心跳：客户端每 30s 发 `ping`，服务端回 `pong`；服务端 90s 收不到任何帧就断开连接。
4. 发消息：客户端生成 `clientMsgId`。网络超时后**用同一个 `clientMsgId` 重发**，服务端会返回与第一次相同的 `msgId` / `seq`，不会产生重复消息。
5. 补拉：客户端为每个会话记录收到的最大 `seq`。重连之后，或者收到的 `seq` 不连续时，发 `sync` 补拉缺失的消息。
6. 聊天室消息没有 `seq`，不支持 `sync`；进房的 `ack` 里会带最近的消息（`recent`）。
7. **实时下发的 `msg` 不保证按 `seq` 顺序到达**（多人同时发言时，投递和落库不在同一把锁里）。客户端必须按 `seq` 排序插入，发现缺口就 `sync`。
8. 同一用户多端在线时，自己发出的消息会以 `msg` 下发到自己的**其他**端，发送端只收到 `ack`。

## 错误码

| code | 含义 |
|---|---|
| 4000 | 帧格式错误 / 参数不合法 |
| 4001 | 未知命令 |
| 4010 | token 无效或过期 |
| 4030 | 无权限（不是群成员等） |
| 4031 | 已被禁言 |
| 4040 | 目标不存在（用户 / 群 / 房间） |
| 4041 | 未加入该聊天室 |
| 4290 | 发送过于频繁 |
| 5000 | 服务端内部错误 |

## 变更规则

- 新增可选字段：向后兼容，直接加。
- 删除或改名字段、改变语义：协议版本号 +1，服务端同时兼容新旧两个版本至少一个发版周期。
- 每次修改协议，都同步补充 `vectors/` 里的用例。
